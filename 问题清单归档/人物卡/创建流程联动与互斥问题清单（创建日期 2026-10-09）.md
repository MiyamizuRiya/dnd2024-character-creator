# 人物卡创建流程联动与互斥问题清单（创建日期 2026-10-09）

> **测试对象**：`DND2024冒险者创建指南.html`（人物卡；本地工作区 main=`c7f981f`，三副本一致）。
> **测试时间**：2026-10-09（聚焦专项：用户报告 3 项 + 同类情况挖掘）。
> **测试方式**：本地 HTTP（127.0.0.1:8797）+ 无头 Edge 154 + 手写 CDP 协议（Runtime.evaluate 驱动页面自身处理函数，等价真实点击）；源码静态核对（`renderSkillPick`/`toggleSkill`/`renderExtraFeatureChoices`/`renderSpellList`/`renderSpeciesChoices`/`pickBg`/`renderToolPick`/`renderBgToolPick`）。**测试期间未修改任何项目文件**。
> **测试范围**：职业技能选择与专精/附赠熟练池的联动、各来源技能熟练互斥（职业/背景/种族/起源专长子项）、法术列表滚动行为、工具熟练互斥、乱序操作（回退改背景/种族）守卫。
>
> **结论摘要**：用户报告的 3 项问题全部复现，并挖掘出 **6 项同类问题**（合计 9 项）：技能熟练在**四个来源**（职业/背景/种族/起源专长子项）与**工具熟练三个来源**（背景工具/职业工具/熟习子项）之间存在系统性互斥缺失；"职业特性"步骤内职业技能选择与下方专精选择区**互不联动**；法术列表选择/移除后**列表框滚动跳顶**（`.spell-list` 容器 DOM 重建）。乱序操作（换背景/种族后）存在 3 类残留状态。整页滚动经小视口验证无跳顶问题（innerHTML 同步替换不影响 window 滚动）。

## 一、用户报告问题（3 项，全部复现）

### U-1【P1 · 联动缺失】选完职业技能后，专精选项不即时出现

- **实测**：吟游诗人 2 级（精灵+侍僧背景）→ "职业特性"步骤 → 专精池显示 `[奥秘,历史,洞悉]`（背景 2 项+精灵敏锐感官 1 项）→ 在上方职业技能网格选 3 项（表演/游说/威吓）→ **下方专精池仍为 `[奥秘,历史,洞悉]`**（`S.chosenSkills` 已更新但 UI 陈旧）；必须离开步骤再回来才刷新。
- **同类**：逸闻学院 3 级「附赠熟练」（`lore_bonus`）池同样不刷新——选"欺瞒"为职业技能后，附赠熟练池 DOM 仍含"欺瞒"可选（选中后即为重复熟练）。法师「学者」、游侠「熟练探险家」等 expertise 型选择与 renderExtraFeatureChoices 同源，全部受影响。
- **根因**：职业技能选择 UI 与专精选择区同在"职业特性"步骤（`go()` 进入该步时同时渲染 `renderSkillPick()` 与 `renderExtraFeatureChoices()`），但 `toggleSkill()`（L1424）末尾只调 `renderSkillPick()`，不刷新 `renderExtraFeatureChoices()`。
- **修法**：`toggleSkill` 末尾追加 `renderExtraFeatureChoices()`。

### U-2【P2 · 互斥缺失】职业技能选择不排除背景已熟练的技能

- **实测**：诗人+侍僧背景（奥秘+历史）→ 职业技能网格 18 项中**「奥秘」「历史」仍可点选**（onclick 存在）→ 点选"奥秘"后 `chosenSkills=["奥秘"]` 与背景重复——玩家实际浪费 1 个职业技能名额（共 3 个）。
- **同类（乱序流）**：先在"职业特性"选了 威吓/表演/游 → 回"起源"换士兵背景（运动+威吓）→ 回来后 `chosenSkills` 仍含"威吓"（与背景重复）；网格中"运动/威吓"仍可点。
- **根因**：`renderSkillPick()`（L1416）`pool = c.skills==="任意"?ALL_SKILLS:c.skills`，无任何排除。
- **规则依据**：熟练项不叠加（2024 PHB）；背景/种族/职业来源重复选择无收益，应从候选中排除。
- **修法**：pool 过滤 `allProficientSkills()`（保留已选项显示）；`pickBg` 时清理 `chosenSkills` 中与背景技能重复项。

### U-3【P1 · 滚动跳顶】选择法术后列表拉回最上面

- **实测**：诗人 5 级 → 法术步骤 → 第一段 `.spell-list` 滚动到 `scrollTop=350` → 点选"化兽为友" → **`scrollTop` 归 0**（DOM 被重建，`afterIsNewDom=true`）；移除已选法术（点已选药丸）同样 `280 → 0`。
- **根因**：`toggleSpell()`（L2783）→ `renderSpellList()`（L2735）`$("spell-sections").innerHTML=allHtml` 整体重建——`.spell-list` 是独立滚动容器（CSS `max-height:480px;overflow-y:auto`，全站唯一自滚动列表容器），新 DOM 的 `scrollTop` 为 0。
- **同类验证**：其他步骤（专精/技能选择）经 900×700 小视口实测整页 `scrollY` 保持 500 不变 ✓（innerHTML 同步替换不产生中间空态，window 滚动不受影响）——**滚动问题仅限法术列表容器**。
- **修法**：`renderSpellList` 重建前记录各段 `.spell-list` 的 `scrollTop`，重建后按索引恢复。

## 二、同类挖掘问题（6 项）

### N-1【P2 · 互斥缺失】种族技能选项（敏锐感官/人类技能）不排除背景已熟练技能

- **实测**：精灵+侍僧背景（洞悉+宗教）→ "起源"步骤敏锐感官选项仍显示 `[洞悉,察觉,求生]`——"洞悉"已因背景熟练仍可选（选了即重复）。
- **根因**：`renderSpeciesChoices()`（L2103）非 isFeat 分支直接渲染 `ch.options`，无排除。
- **修法**：选项过滤 `allProficientSkills()`（保留当前已选值显示）。

### N-2【P2 · 状态残留】换背景后，种族子选项已选值与背景技能重复不清理

- **实测**：精灵已选敏锐感官=洞悉 → 换侍僧背景（洞悉+宗教）→ `S.speciesChoices['敏锐感官']` 仍为"洞悉"——与背景重复且 UI 无提示。
- **修法**：`pickBg` 时若背景技能与「人类技能/敏锐感官」已选值重复，清除并 toast 提示重选。

### N-3【P2 · 互斥缺失】起源专长子项（熟习）选项不排除已熟练技能/工具

- **实测**：人类+熟习（侍僧背景）→ 熟习子项 49 个选项（18 技能+31 工具）中，背景技能"洞悉""宗教"仍可选中——重复熟练。
- **根因**：`renderSpeciesChoices()`（L2091）isFeat 分支的 `fc.options.forEach` 无排除（对照：逸闻学院附赠熟练池 L1726 已正确排除 `allProficientSkills()`）。
- **修法**：子项选项过滤——技能按 `allProficientSkills()`、工具按新增 `allProficientTools()`（保留已选显示）。

### N-4【P2 · 状态残留】取消职业技能熟练后，已选专精残留（非法状态）

- **实测**：诗人 2 级，`chosenSkills=[表演,游说]`，专精已选 `[表演,游说]` → 取消"表演"的职业技能熟练 → `S.featureChoices['bard_expertise']` 仍为 `[表演,游说]`——**"表演"已不熟练却仍带专精**（专精要求技能已熟练）。
- **修法**：`toggleSkill` 移除技能时，从 expertise 型 `featureChoices` 中同步移除该技能并 toast。

### N-5【P2 · 互斥缺失】工具熟练三向互斥全缺（背景工具/职业工具/熟习工具）

- **实测（代码级+数据验证）**：背景工具选择（`renderBgToolPick` L1918）、职业工具选择（`renderToolPick` L1888，吟游诗人 3 乐器/武僧 1 工具或乐器/工匠职业 1 工匠工具）、熟习子项工具（31 项）三者互不排除——例如背景选了"骰子游戏"后熟习子项仍可选"骰子游戏"；职业乐器选了"鲁特琴"后换到乐器背景仍可选"鲁特琴"。
- **修法**：新增 `allProficientTools()`（`S.bgTool`+`S.toolChoices`+熟习子项工具项）；`renderBgToolPick`/`renderToolPick`/熟习子项渲染三处过滤（保留已选显示）。

### N-6【P3 · 联动防御】种族/背景/专长变更不联动"职业特性"步骤选择区（乱序流）

- **实测（代码级）**：`pickSpecies`/`pickSpeciesChoice`/`toggleFeatChoice`（起源步骤内操作）均不调 `renderSkillPick`/`renderExtraFeatureChoices`/`renderToolPick`——正常流程下靠 `go()` 导航时重渲染兜底，但乱序操作后立即读取 DOM 的场景（如 A2C 校验 `speciesChoicesComplete` 后回 features 前的中间态）无保障。
- **修法**：三个函数尾部追加保险联动渲染（features 步骤 DOM 常驻页面仅隐藏，渲染无副作用）。
