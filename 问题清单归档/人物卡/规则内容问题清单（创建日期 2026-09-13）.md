## 二、问题清单

### P0-1 角色卡法术行显示固定数值且标签错误

**位置：** `DND2024冒险者创建指南.html:2228-2230`

```js
html+=`已选戏法(${c.cantripsKnown||0}): ${S.chosenCantrips.join("、")||"(未选)"}`;
const sn=c.spellsKnown||c.prepSpells||c.spellbookL1;
html+=`已选1环法术(${sn||0}): ${S.chosenSpells.join("、")||"(未选)"}`;
```

这三个字段取的是 `CLASSES` 里**写死的 1 级数值**，不随等级变化；且标签语义错误（把"准备数/法术书容量"写成"1环法术数"）。

| 角色 | 卡片显示 | 应为 |
|---|---|---|
| 牧师 20 级 | `已选戏法(3)` / `已选1环法术(4)` | 5 个戏法；准备 22 个（含 1-9 环） |
| 术士 20 级 | `已选1环法术(2)` | 准备 22 个 |
| 法师 20 级 | `已选1环法术(6)` | 法术书 46 个（准备 25 个） |
| 圣武士 15 级 | `已选1环法术(2)` | 准备 12 个 |
| 魔契师 20 级 | `已选1环法术(2)` | 准备 15 个 |

**影响：** 玩家直接看到的角色卡文本 + 导出的 `.txt` 内容，高等级角色普遍显示错误。
**修法：** 改用已有的 `spellCantripCount()` 与 `spellTotalCount()`；标签按职业区分"准备/已知/法术书"。

### P0-2 兼职施法者准备数虚高，出现"选不满"空位

**位置：** `spellTotalCount()` `:1929-1932`（配合 `classSpellList()` `:1902`）

圣武士/游侠的准备数用 `Math.max(1, sm+lv)` 计算（这是 2024 版专职公式），而可选法术被 `maxSpellLevelByClass` 正确限制在本职业环阶上限内。两者组合后容量大于实际可选项：

| 等级 | 官方准备数 | 工具容量 | 环阶上限 | 环阶内可选数 | 差异 |
|---|---|---|---|---|---|
| 5 | 6 | 7 | 1-2 环 | 6 | 空 1（无害） |
| 7 | 7 | 9 | 1-2 环 | 8 | 空 1（无害） |
| **9** | **9** | **11** | 1-3 环 | **9** | **容量 11 > 可选 9** |
| **11** | **10** | **13** | 1-3 环 | **11** | 容量 13 > 可选 11 |
| **13** | **11** | **15** | 1-3 环 | **13** | 容量 15 > 可选 13 |

规则原文（游侠 1 级施法）："你所选择法术的环阶**必须是你所拥有法术位对应的环阶**"。9 级游侠只有 1-3 环位，不能准备三环以上——工具在这一点是对的。问题在于**显示容量 11 而环阶内只有 9 个可选项**，玩家以为还有法术可挑，筛选后却出现"无匹配法术"。

**修法：** 半施法者准备数直接用官方表（`2,3,4,5,6,7,9,10,11,12,14,15`），或至少把"总容量"与"当前环阶可选数"分开提示。

### P0-3 子职施法者（奥法骑士/诡术师）法术位计算完全错误

**位置：** `slotsStruct()` `:2518-2522`、`multiclassSpellSlotsText()` `:2124-2126`

两处都用 `FULL_CASTER_SLOTS[Math.floor(S.level/3)]`——**把战士/游荡者等级当作施法者等级，去查全施法者 9 环表**；而官方子职施法者表最高只有 4 环，且法术位数明显更少。

| 等级 | 官方 一/二/三/四 | 工具实际 |
|---|---|---|
| 3 | 2 / — / — / — | 2 |
| 5 | 3 / — / — / — | 3 |
| **7** | **4 / 2 / — / —** | **4 / 3 / 2** |
| 10 | 4 / 3 / — / — | 4 / 3 / 3 / 1 |
| **13** | **4 / 3 / 2 / —** | **4 / 3 / 3 / 3 / 1** |
| 16 | 4 / 3 / 3 / — | 4 / 3 / 3 / 3 / 2 |
| **19** | **4 / 3 / 3 / 1** | **4 / 3 / 3 / 3 / 3 / 2 / 1** |
| 20 | 4 / 3 / 3 / 1 | 4 / 3 / 3 / 3 / 3 / 2 / 2 / 1 |

19 级奥法骑士会被显示为拥有 3 个六环位、2 个七环位、1 个八环位——**这些都是不存在的法术位**。

注意 `maxSpellLevel()` `:1885-1892` 算的是对的（3/7/13/19 级对应 1/2/3/4 环），所以玩家**实际选不到**这些高位法术，但角色卡会告诉他有——正是"显示有、实际没有"。

**修法：** 单独建 `SUBCLASS_CASTER_SLOTS` 表（键为战士/游荡者等级）。官方「奥法骑士施法表」与「诡术师施法表」两表完全相同：

```
等级  一环 二环 三环 四环
 3     2   —    —    —
 4-6   3   —    —    —
 7-12  4   2    —    —
13-15  4   3    2    —
16-18  4   3    3    —
19-20  4   3    3    1
```

### P1-4 子职施法者准备数估算不准

**位置：** `spellTotalCount()` `:1922-1926`

```js
if((c.id==="fighter"&&S.subClass==="奥法骑士")||(c.id==="rogue"&&S.subClass==="诡术师")){
  const fa=finalAbi();
  const sm=mod(fa["智力"]);
  return Math.max(1,sm+Math.floor(lv/3)+1);   // ← 估算，非官方表
}
```

代码注释自己也写了"简化:用智力调整值+floor(等级/3)+1"。该估算与官方表偏差：

| 等级 | 智力 10 (mod 0) 工具值 | 官方 | 差 |
|---|---|---|---|
| 3 | 3 | 3 | ✓ |
| 5 | 3 | 4 | −1 |
| 7 | 3 | 5 | −2 |
| 10 | 4 | 7 | −3 |
| 16 | 6 | 11 | −5 |
| 20 | 8 | 13 | −5 |

低智力高等级角色最明显：16 级奥法骑士工具只给 6 个准备位，官方是 11 个——**玩家选了智 10 就会被限制"能选却选不满"**。

**修法：** 改用官方表 `3,4,4,4,5,6,6,7,8,8,9,10,10,11,11,11,12,13`（奥法骑士与诡术师同表）。

### P1-5 兼职熟练项（MULTICLASS_PROF）5 处与规则不符

**位置：** `DND2024冒险者创建指南.html:957-970`

各职业"作为兼职角色"段落原文要求如下。加粗为工具错误项：

| 职业 | 工具显示 | 官方原文 | 问题 |
|---|---|---|---|
| 吟游诗人 | 轻甲、**简易武器**、任选1项技能熟练 | 生命值骰，任选一项技能熟练，**任选一项乐器熟练**和轻甲 | 漏乐器；多给简易武器 |
| 牧师 | 轻甲、中甲、盾牌、**简易武器** | 生命值骰，轻甲、中甲和盾牌 | 多给简易武器 |
| 德鲁伊 | 轻甲、中甲(非金属)、盾牌(非金属)、**简易武器** | 生命值骰、轻甲和盾牌 | 多给简易武器；盾牌"非金属"限制多余 |
| 战士 | **轻甲、中甲、盾牌**、简易和军用武器 | 生命值骰、军用武器熟练以及轻甲、中甲和盾牌 | 表述造成误导（见下） |
| 游荡者 | 轻甲、简易武器和**具灵巧或轻型词条的军用武器**、盗贼工具 | 轻甲、简易武器、盗贼工具 | 多给军用武器 |

战士一项需特别说明：官方确实给了"轻甲、中甲和盾牌"，但兼职者通常已经拥有这些熟练，官方这句话的语义是"不丢失"。工具把它列为"兼职获得"，玩家可能误以为兼职战士能额外获得什么——建议改为提示性文字。

**影响：** 兼职牧师/德鲁伊的简易武器、兼职游荡者的军用武器熟练在规则中不存在，但角色卡明确写了"兼职获得"，属于**不该有却说有**。

### B. 与已知坑的关联

- 本次 P0-2 的"容量大于可选项"与项目文档记录的 P2-4（子职法术结构化）同源：法术可选列表依赖 `spellTotalCount()` 与 `maxSpellLevelByClass()` 两处独立计算，任一处口径变化都会产生新的"能选/不该选"偏差。建议后续把两者合并为一个函数返回 `{count, maxLevel, note}`。
- P0-3 的法术位显示走 `slotsStruct()`，与 `maxSpellLevel()` 分属两套表——同类口径分裂，建议一并收敛。
