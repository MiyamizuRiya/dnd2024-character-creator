## 二、P0 级（功能性错误，直接输出错误数值/规则）

### P0-1 兼职施法等级换算漏掉奥法骑士/诡术师（三处连锁）

**位置：** `casterLevelForClass()` L993-997、`slotsStruct()` L2617-2620、`maxSpellLevel()` L1939-1945

官方兼职规则原文（`创建角色/兼职.htm`，已核对）：

> 你所有的吟游诗人、牧师、德鲁伊、术士和法师等级。**你的圣武士和游侠等级的一半（向上取整）。如果你选有奥法骑士子职，你的战士等级的三分之一（向下取整）；如果你选有诡术师子职，你的游荡者等级的三分之一（向下取整）。**

工具三处偏差：

1. `casterLevelForClass()` 对 fighter/rogue 恒返回 0 —— EK/AT 的 1/3 贡献从未计入 `totalCasterLevel()`。
   例：战士 6(奥法骑士)/法师 5 → 官方施法等级 = 2+5 = 7；工具 = 5（少 2 环法术位 1 个）。
2. `slotsStruct()` 的 EK 分支用 **总等级** `S.level` 查 `SUBCLASS_CASTER_SLOTS`（应按战士职业等级）。例：战士 5(EK)/游荡者 2 → 总 7 级，工具按 7 级行给法术位。
3. 该分支在有其他施法兼职时**提前 return**，永远用子职表而不用合并表；反向兼职（主职业法师 + 兼职进 EK）则完全不进该分支，法术位为 0。

**修法：** ① `casterLevelForClass` 增加 `if((classId==="fighter"&&S.subClass==="奥法骑士")||(classId==="rogue"&&S.subClass==="诡术师")) return Math.floor(classLevel/3);`（兼职侧同样读取 `mc.subClass`）；② `slotsStruct`/`maxSpellLevel`/`multiclassSpellSlotsText` 统一改用职业等级，且只要存在兼职施法者就并入 `totalCasterLevel()` 查全施法表（子职表仅用于"无其他施法来源"时的纯单职业展示）。

### P0-2 `isSpellcaster()` 不识别兼职施法职业

**位置：** L1109-1117

```js
function isSpellcaster(){
  const c=curClass();
  if(!c) return false;
  if(c.spell) return true;
  if(c.id==="fighter" && S.subClass==="奥法骑士") return true;
  ...
}
```

只看主职业。**主职业选了非施法者（如野蛮人）、再兼职法师**时，`isSpellcaster()` 返回 false → `maxSpellLevel()`=0、`slotsStruct()` 为空、法术选择界面整体不出现。兼职恰恰是最需要它的场景。

**修法：** 追加 `if(S.multiclass.some(m=>CLASSES.find(x=>x.id===m.classId)?.spell)) return true;`（以及 mc 侧 EK/诡术师判断）。

### P0-3 超魔法获取进度：起点晚一级、增量各少一半

**位置：** `metamagicLevels()` L619-627

官方（术士页，已核对）：**2 级**获得 2 个超魔法选项；**10 级和 17 级分别再获得 2 个**（即 2/4/6）。

| 等级 | 官方累计 | 工具给出 |
|---|---|---|
| 2 | 2 | 0（3 级才起步） |
| 3-9 | 2 | 2 |
| 10-16 | 4 | 3 |
| 17-20 | 6 | 4 |

**修法：** `if(S.level>=2) result.push({lv:2,count:2}); if(S.level>=10) result.push({lv:10,count:2}); if(S.level>=17) result.push({lv:17,count:2});`（UI 按"每档可再选 N 个"消费；工具自带 `CLASS_FEATURES.sorcerer` 原文即写 2 级/各 +2。）

### P0-4 战斗大师战技数不随等级增长

**位置：** `maneuverLevels()` L628-633

官方（战斗大师页，已核对）：3 级习得 3 种战技；**第 7、10、15 级各习得 2 种新战技**（累计 3/5/7/9）。工具固定返回 3 个。另：卓越骰 4 枚起、7 级 5 枚、15 级 6 枚、10 级升 d10、18 级升 d12，如后续做骰池可一并考虑。

**修法：** `const r=[]; if(S.level>=3)r.push({lv:3,count:3}); if(S.level>=7)r.push({lv:7,count:2}); if(S.level>=10)r.push({lv:10,count:2}); if(S.level>=15)r.push({lv:15,count:2}); return r;`

## 四、P2 / P3 级

### P2-11 战士 11/20 级特性描述文本错误（L1064 `CLASS_FEATURES` 行内）

「额外攻击（二）」(11 级)与「额外攻击（三）」(20 级)描述均为"可以发动**两次**攻击而非一次"。官方：11 级=**三次**、20 级=**四次**。此文本会流入等级信息/导出文件。

### P2-12 精灵敏锐感官 / 人类技能熟练无选择 UI

- 精灵 L368 特性文本已写「洞悉、察觉或求生任选一项熟练」，但 `choices` 只有精灵血系+施法属性，没有技能单选 → 角色卡技能栏永不体现。
- 人类 L375-376「获得一项自选技能熟练」同样无 UI（人类专长选择已有）。

**修法：** 仿血系施法属性加一个三选一/十八选一下拉，选中项并入 `S.chosenSkills` 参与角色卡技能行与被动察觉计算（精灵若选察觉，被动察觉应+熟练加值）。

### P2-13 背景「噩梦缠身者」非 PHB2024 内容（L415）

规则站目录确认其出处为 `鸦阁魔域：魔障深藏/第一章/背景/噩梦缠身者.htm`（Van Richten's Guide to Ravenloft）。PHB2024 背景=16 个，与前 16 个完全一致。若工具定位纯 2024 规则应移除；若有意保留（丰富可玩性），建议在背景卡上标注「扩展规则：VRGtR」，避免与"PHB2024"宣称混淆。

### P2-14 等级信息板 EK 环阶公式自相矛盾（L2397）

`maxSpellLevelByClass('wizard',Math.floor(lv/3))`：7-8 级显示 1 环（实为 2 环）、13-14 级显示 2 环（实为 3 环）、19-20 级显示 3 环（实为 4 环）；而法术选择的 `maxSpellLevel()` L1939-1945 用的是正确的 3/7/13/19 断点。信息板与选择器互相打架。**修法：** 信息板直接调用 `maxSpellLevel()`。

### P3-15 `SPECIES_DESC_LONG` 键名 typo（L556）

键 `aasimo:` 应为 `aasimar:`。用途处 `(SPECIES_DESC_LONG[s.id]||s.desc)` 查不到就回退短描述，故阿斯莫的种族详情弹窗永远显示一句话简介，其余 9 个种族正常。改一个键名即修。
