## 1 · R1+R3 · 技能译名统一为 2024 官方译名「特技」(本轮最高优先)

**根因**:`SKILL_ATTR`/`ALL_SKILLS`(手写表)用 2014 社区译名「杂技」,而职业/背景数据(5echm 2024 抓取)用 2024 官方译名「特技」。三处后果:
① 职业技能列表 `SKILL_ATTR["特技"]` → undefined(R1 显示);
② 角色表技能加值 `mod(fa[SKILL_ATTR[s]||'力量'])` → 特技按力量计算(R1 数值错误);
③ 人类技能列表显示「杂技」、职业列表显示「特技」,同技能双名,角色表按名去重失效(R3)。

**修复(统一为「特技」,`DND2024冒险者创建指南.html`)**:

① `ALL_SKILLS`(约 23160 字符处)与 `SKILL_ATTR`(约 23174 字符处):把 `"杂技"` 全部改为 `"特技"`:

```js
const ALL_SKILLS=["运动","特技","巧手","隐匿","奥秘","历史","调查","自然","宗教","驯兽","洞悉","医药","察觉","求生","欺瞒","威吓","表演","游说"];
const SKILL_ATTR={"运动":"力量","特技":"敏捷","巧手":"敏捷", ... 其余不变};
```

② **旧档迁移**(旧进度文件/localStorage 里已选的「杂技」):`loadState()` 与 `importProgressFile()` 的状态应用处,加一行归一化:

```js
// loadState 内 S 载入后 / importProgressFile 的 Object.assign 后:
const fixSkillName = n => n === "杂技" ? "特技" : n;
["chosenSkills"].forEach(k => { if (Array.isArray(S[k])) S[k] = S[k].map(fixSkillName); });
if (S.speciesChoices) for (const k in S.speciesChoices) S.speciesChoices[k] = fixSkillName(S.speciesChoices[k]);
if (S.featChoices) for (const k in S.featChoices) S.featChoices[k] = (S.featChoices[k]||[]).map(fixSkillName);
```

③ **防再犯兜底**:`renderSkillPick` 的选项模板属性名与 `renderSheet` 技能行,`SKILL_ATTR[sk]` 改 `SKILL_ATTR[sk]||"—"`(角色表侧可保留 `||'力量'` 换成 `||"—"` 并跳过加值,避免未来再缺键时给出错误数值):

```js
// renderSheet 技能行(约 2471 行附近):
uniq.map(s=>{ const a=SKILL_ATTR[s]; const m=a?mod(fa[a])+prof:0; return a? s+' '+pb(m) : s; })
```

**验证**:
1. 战士/武僧/游荡者职业卡技能列表显示「特技 敏捷」,无 undefined;
2. 力量 8/敏捷 15 的战士选特技 → 角色表「特技 +4」(=2 熟练+2 敏捷);
3. 人类技能列表显示「特技 敏捷」;导入含「杂技」的旧进度 → 自动归一为「特技」;
4. 战士特技 + 人类技能特技 → 角色表技能行只出现一条(去重生效);
5. `node build.js` 三副本一致后回归:购点超支/A2 同步/熟习并入不回退。

## 4 · R4 · 拼音搜索离线化(低优先,可排期)
