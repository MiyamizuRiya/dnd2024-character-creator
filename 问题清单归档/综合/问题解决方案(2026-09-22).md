## P1-1 · A2 天赋法术同步失效

**根因**:三个工具在合集中都是 blob-URL iframe。真机实测 blob iframe 内 `window.parent.frames` 为 undefined,`p.frames[i].postMessage(...)` 抛 TypeError 被 `catch{}` 吞掉,同步静默失效。`parent.document` 可访问(同源),是可靠的寻帧通道。

**修复 1/2 —— 人物卡广播**(`DND2024冒险者创建指南.html:2860`,`function broadcastGranted()`):

```js
function broadcastGranted(){
  try{var data={type:'dnd:granted',spells:grantedSpells()};var p=window.parent;
    if(p&&p!==window){
      var sent=false;
      try{
        // blob iframe 中 parent.frames 不可用(实测 length===undefined);
        // blob 与父页同源,经 parent.document 按 iframe title 寻帧投递
        var doc=p.document;
        if(doc){['法术书生成','魔法物品卡'].forEach(function(t){
          var f=doc.querySelector('iframe[title="'+t+'"]');
          if(f&&f.contentWindow){f.contentWindow.postMessage(data,'*');sent=true;}
        });}
      }catch(e){console.warn('broadcastGranted 寻帧失败:',e)}
      try{p.postMessage(data,'*');}catch(e){}
      if(!sent&&window.console)console.warn('broadcastGranted:未送达任何兄弟 iframe');
    }
  }catch(e){console.warn('broadcastGranted:',e)}
}
```

**修复 2/2 —— 法术书请求握手**(`法术书生成/js/app.js:694`,`function requestGrantedSpells()`):

```js
function requestGrantedSpells() {
  try {
    var msg = { type: "dnd:requestGranted" };
    var p = window.parent;
    if (p && p !== window) {
      try {
        var doc = p.document; // 同上:parent.frames 在 blob iframe 中不可用
        if (doc) ["冒险者创建指南", "魔法物品卡"].forEach(function (t) {
          var f = doc.querySelector('iframe[title="' + t + '"]');
          if (f && f.contentWindow) f.contentWindow.postMessage(msg, "*");
        });
      } catch (e) { console.warn("requestGrantedSpells:", e); }
      try { p.postMessage(msg, "*"); } catch (e) {}
    }
  } catch (e) {}
}
```

> 人物卡侧的**应答**用 `e.source.postMessage(...)`(已有代码),该 API 在任意 WindowProxy 上都可用,无需改动。物品卡无监听,收到也无害。
> 改完跑 `node build.js`(两处都在被内联的源码里)。
> **验证**:合集页建提夫林(炼狱遗赠)→ 不做任何其他操作切到法术书 → 应见「已从角色卡同步 1 个天赋法术」且火焰箭入卡。

## P1-3 · 施法职业的「魔法学徒」(MI)被忽略

**现状**:MI 只在 `isSpellcaster()` 的"非职业施法"分支生效;主职业是施法者时,MI 的 2 戏法 + 1 一环凭空消失。

**方案**(三处,均在 `DND2024冒险者创建指南.html`):

① `spellCantripCount()`(约 2040 行):主职业分支的返回值**加 MI 的 2 道戏法**:

```js
function spellCantripCount(){
  if(!isSpellcaster()) return 0;
  const p=primaryCaster();
  if(!p) return magicInitiateInfo()?2:0;
  // ……原有各职业计算,记结果为 n ……
  const mi=magicInitiateInfo();
  return n + (mi?2:0);        // ← MI 的 2 道戏法(与职业列表相同时由去重保证不重复显示)
}
```

② `spellTotalCount()`(2052 行):同理,主职业为施法者时 `+1`(MI 的一环,建议按"额外常备"处理,不占书内/准备位):

```js
  const mi=magicInitiateInfo();
  if(mi) return 原有结果 + 1;   // 注:MI 一环按常备口径,需在 alwaysPreparedSpells() 里
                                 // push(magicInitiateInfo().首环法术名, "魔法学徒(背景)")
```

③ `classSpellList()`(2010 行):`spellClassName` 之外,把 MI 列表职业的法术并入选择范围(仅 戏法+一环):


④ `renderSpellUI()` 提示文案补一句「魔法学徒(背景):额外 2 戏法 + 1 个一环常备」;`renderSheet` 的【始终准备的法术】来源里出现"魔法学徒"。

## P1-4 · 兼职第二施法职业无法选法术

- `classSpellList()` 增加参数 `className`;`spellTotalCount()`/`spellCantripCount()` 增加参数按段计算;
- `renderSheet` 法术总览按段列出,常备表不变。
改动集中在 `renderSpellUI/renderSpellList/toggleSpell/计数函数/renderSheet` 约 60 行。

**方案 B(最小,先堵误导)**:维持单列表,但:
- `renderSpellUI()` 提示补:「⚠ 兼职施法职业(牧师 1 级)的准备法术请在规则书中自行选择,本工具暂未提供其列表」;
- `renderSheet` 法术总览标注「以上仅统计主职业」。
5 行改动,先消除误导,方案 A 排期再做。

**验证(A)**:法师 2+兼职牧师 1 → 法术步骤出现牧师段,可选 4 个一环牧师法术;总览分别列出。
