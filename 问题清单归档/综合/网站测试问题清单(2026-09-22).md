## 一、问题清单(按严重程度)

### P1 · 功能缺陷(影响核心体验)

**1. A2「天赋法术同步」在真实浏览器中完全失效**
- 现象:人物卡选中提夫林「炼狱」遗赠后,`grantedSpells()` 返回 `["奇术","火焰箭"]`,但合集中的法术书 iframe 收不到,已选数不变、无「已从角色卡同步」提示;手动调用 `broadcastGranted()` 同样无效。
- 根因:blob-URL iframe 中 `window.parent.frames` 不可用(实测 `parent.frames.length === undefined`),`broadcastGranted()`(人物卡,`DND2024冒险者创建指南.html:2860`)与 `requestGrantedSpells()`(法术书,`法术书生成/js/app.js:694`)的 `for(...) p.frames[i].postMessage(...)` 抛 `TypeError` 后被 `catch{}` 静默吞掉。文档(AI背景说明 §六)宣称「合集三个 iframe 时此机制依然有效」,但 §九.7 注明"真机渲染未实测"——本次实测证伪。
- 已验证的修复方向:改为 `window.parent.document.querySelector('iframe[title="法术书生成"]').contentWindow.postMessage(data,"*")` 后同步立即生效(blob iframe 与父页同源,`parent.document` 可访问)。
- 建议:两个函数统一改用 `parent.document` 寻帧发送;`catch` 中至少 `console.warn`,别静默。

**2. 子职面板不随等级变化刷新:「先选职业、后改等级到 3 级」的玩家在职业步骤看不到子职选择**
- 现象(对照实验确证):流程 A「先设 3 级、再选职业」→ 职业步骤下方的子职选择区正常显示该职业子职;流程 B「1 级选职业 → 再把等级改为 3 级」→ 子职选择区保持隐藏(且内容残留上一个角色的子职列表,实测残留法师四子职)。通过「⬆ 升级」按钮升到 3 级则正常(applyLevelUp 走了 renderEverything)。
- 补充:子职选择区(`subclass-pick-wrap`)实际位于**职业步骤**面板内(并非独立的「进阶」步骤);「进阶」步骤只管兼职分配。主线「下一步」按钮从职业步骤直接跳起源,不经过任何子职提示。
- 根因:`renderSubclassPick()`(`DND2024冒险者创建指南.html:1445`)只在 `pickClass`/`renderClassInfo`/`go('class')`/`pickSubclass`/`renderEverything`/`loadState` 时执行;`pickLevel()`(2422)不刷新它,且 `level<3` 时只 `addClass("hide")` 提前返回、不清空旧内容。
- 建议:`pickLevel()` 中补 `renderSubclassPick()`(一行);或等级变化跨过 3 级阈值时 toast 提示去选子职。

**3. 施法职业获得背景「魔法学徒」(Magic Initiate)后,法术步骤完全忽略该专长**
- 现象:法师 + 智者背景(魔法学徒(法师))实测:法术步骤仍只给「3 戏法 + 6 书内法术」,MI 的 2 戏法 + 1 个一环无处可选,角色表法术总览也不显示 MI 内容。非施法职业(如野蛮人)+ MI 的路径已实现(2026-09-12 批次),施法职业路径缺失。
- 相关代码:`magicInitiateInfo()`(1113)只用于 `isSpellcaster()` 的非职业施法分支;`spellCantripCount`/`spellTotalCount`(2052)/`classSpellList`(2010)均未合并 MI。
- 建议:施法职业 + MI 时,戏法上限 +2、法术上限 +1(MI 的一环法术按"额外常备"处理,计入法术总览)。

**4. 兼职第二个施法职业无法选择其法术**
- 现象:实测法师 2 级 + 兼职牧师 1 级后,法术步骤只显示法师法术(书内 8 个),牧师侧「准备法术」(官方表 1 级 = 4)完全无法选择;法术总览也只统计主职业。法术**位**计算(4 个一环 + 2 个二环)已正确合并,法术**选择**未合并。
- 相关代码:`classSpellList()`(2010)只按 `primaryCaster()` 的单职业过滤;`spellTotalCount()`(2052)只统计主职业。
- 建议:法术列表按"主职业 + 各兼职施法职业"分段提供(各自计数/各自列表),或在当前架构下明确在 UI 中说明"兼职职业的法术请自行查阅规则书"(至少不误导)。

### P2 · 体验与正确性(中)

**5. 合集「☰ 选择工具」按钮遮挡人物卡顶栏「🗑 清空记录」按钮**
- 现象:窗口宽 1200px 实测两按钮几何重叠(1440px 下仅 3px 重叠,更窄时更严重);toggle 按钮 z-index 999999 会拦截点击。法术书/物品卡因 `embedded` 类留出 130px 不受影响,人物卡未做让位(`embedded=false`)。
- 相关代码:合集模板 `#toggle`(build.js 内模板)、人物卡 `.head-actions`。
- 建议:人物卡同样检测 `embedded` 并给顶栏右侧留白,或把 toggle 移到左上角。

**6. 购点法超支不拦截,可带超支属性继续建卡**
- 现象:购点法下把多项属性买到 15(总花费 34/27)后,UI 仅显示「已用 34 / 27 点 (超支!)」文字提示,不阻止继续「下一步」;属性值保留超支状态进入后续步骤与角色表。
- 相关代码:`setManual`(购点分支只钳制 8~15 单值,不校验总点数)、`updatePoint`。
- 建议:超支时禁用「下一步」按钮,或自动回退最后一笔超支修改。

**7. 人类「技能」子选项每项下方显示 "undefined"**
- 现象:人类种族选择「技能:选择一项技能熟练」时,18 项技能每项下方都显示 `undefined`(应为智力/感知等属性名)。职业技能列表(如法师)显示正常。
- 相关代码:`renderSpeciesChoices()`(1699)人类技能分支的属性名取值字段不存在。
- 建议:修正字段引用,与职业技能行同一口径。

**8. 「熟习」(Skilled)专长获得的熟练项未并入角色表**
- 现象:人类选「熟习」专长 → 选「察觉」,角色表「技能熟练」仍只显示 奥秘 +5、历史 +5;察觉(应 +4)不出现,且「被动察觉」仍为 12(=10+感知2),未计入察觉熟练(应为 14)。2026-08-28 清单 C12 曾记录同类问题,人类"技能"选择已修(2026-09-12),但"熟习"专长路径仍是漏的。
- 相关代码:`renderSheet()`(2305)技能行/被动察觉的计算。
- 建议:把 `S.featChoices` 中熟习/巧匠等提供的熟练统一并入技能行与被动察觉。

**9. 种族子选项未选完可静默跳过**
- 现象:人类子选项(多才多艺专长、技能)未选时,点「下一步:确定属性」直接通过;角色表显示「人类技能: (未选)」。无校验、无提示。
- 建议:子选项有必选项时,点下一步弹 toast 提醒(或允许跳过但角色表用醒目样式标注未完成)。

**10. 法术书角色名输入不即时刷新页标签**
- 现象:顶栏输入角色名后,页眉「第 X 页 / 共 Y 页」不实时带名字;需触发下一次重渲染(选/删法术、排序等)后才出现。
- 相关代码:法术书 `renderPreview()`(`法术书生成/js/app.js:303`)每次读取 `#charName` 值,但该输入框无 `input` 监听。
- 建议:给 `#charName` 加 `input` 监听触发 `renderPreview()`。

**11. 角色表「已准备 N 个」与法师实际准备数不一致(文案误导)**
- 现象:1 级法师提示「抄录 6 个入法术书;当前可准备 4 个」,但角色表法术总览把 6 个书内法术标为「已准备 6 个」。
- 建议:文案改为「法术书内 6 个 / 可准备 4 个」并区分展示(与 2026-09-03 修复的 C14 口径一致)。

### P3 · 低危/文案/杂项

**12. 物品数据 417 条,文档与入口页均写 419 条**
- 实测 `data/items.js` 的 `ITEM_DATA.length === 417`;`README.md`、`AI背景说明.md` 与合集入口卡文案均写「419 条魔法物品」(build.js 模板中写死)。差 2 条,需确认是数据误删还是文案过期。
- 建议:核对数据源,统一为实际条数(或补回缺失条目)。

**13. 用户输入原样进入导出文件名**
- 实测角色名填 `<img src=x onerror=...>梅林` 后,导出进度文件名为 `_img_src=x_onerror=window.__xs-DND2024进度-2026-09-22.md`(浏览器自动清洗后的残片)。内容本身安全(全站 XSS 已防护,实测 `onerror` 不执行),但文件名会脏。
- 建议:导出文件名对角色名做 `[^\w\u4e00-\u9fa5]` 过滤或使用固定前缀。

**14. 全站缺少 favicon**
- 所有页面请求 `/favicon.ico` 均 404(控制台持续报错)。建议补一个 ico 或 `<link rel="icon" href="data:,">` 空占位。

**15. 升到 3 级后未按文档"自动跳去选子职"**
- 文档(2026-09-11 批次)称 applyLevelUp「3 级自动跳去选子职」,实测升到 3 级后停留在职业步骤(active=职业)。因子职面板就在职业步骤内且经升级路径已正确渲染,功能可用,属文档与实现不符 + 提示不足。
- 建议:升级到 3 级时 toast「请在职业页选择子职」或滚动定位到子职区。

**16. 物品卡缺「消耗品」筛选开关**
- 数据带消耗品标记(列表徽章/卡片徽章均有),但筛选区只有「仅需同调 / 仅显示已选」;法术书有仪式/专注两个特性开关,物品卡没有对应的消耗品开关。做药水/卷轴清单时只能靠搜索。
- 建议:筛选区补「仅消耗品」开关(数据现成)。

**17. 掷点/数列的"每值只用一次"防线仅在 UI 层**
- 实测:`setArray`/`setRollAssign` 函数本身不校验重复,靠渲染时给已用选项加 `disabled`(正常用户无法选到重复值,功能有效);但任何脚本/异常路径可直接写入重复值。属纵深防御缺口,不影响正常使用。
- 建议:函数内补一行重复检查(低优先)。

**18. 法术书偶发一次页面冻结(未能稳定复现,低置信)**
- 一轮测试中,合集内法术书在点选第 6 个法术时渲染线程卡死(持续 >1 分钟,Runtime.evaluate 全部超时、无任何 JS 异常记录);同序列在全新标签页两次复现均正常。另一次"卡死"已查明是独立页 `confirm()` 对话框未被自动化应答所致(测试环境因素,非产品问题)。
- 建议:留意观察;若再出现,优先检查 `computeSizes`/`packPages` 在 `rowsPerPage=4` + 卷轴模式组合下的表现。

## 三、环境与工程注意事项

**19. 本机找不到 Node,`node build.js` 无法执行**
- 在 PATH、常见安装目录、nvm/Program Files 等位置均未找到 `node.exe`(spawn 报 ENOENT)。接入指南的日常循环要求「改源码必须 `node build.js`」,电脑 B 需要先安装 Node(https://nodejs.org)并确保在 PATH 中。
- 注意:本次测试未执行构建,构建脚本本身未做回归;当前三副本一致,说明现有构建产物与源码同步。

**20. 本机 Git Bash 全线崩溃(与项目文档 §九.1 已知坑一致)**
- MSYS2 fork 失败(`STATUS_DLL_INIT_FAILED` / `child_copy` Win32 error 299),连 `echo` 都无法运行,疑似杀毒软件注入所致。影响:`git`、`unzip`、`node build.js` 等全部 shell 命令不可用。
- 两轮测试均已绕行:全程用 Node 直调完成文件操作、本地服务器与浏览器驱动。
- 建议:重启电脑或临时关闭杀毒软件;长期方案参考项目文档,文件/命令操作一律走 Node 直调。
