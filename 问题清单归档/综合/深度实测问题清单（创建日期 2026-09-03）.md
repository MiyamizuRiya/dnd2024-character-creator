## 1. 本轮实测新发现的 Bug

### 1.1 🔴 [严重] 模糊搜索阈值过低,2 字查询误伤 80~92% 数据

**实测证据**(法术书,干净单次查询):

| 搜索词 | 期望命中 | 实测返回 | 误伤率 |
|---|---|---|---|
| `火球术`(唯一精确名) | 1 | **327** | 84% |
| `火球` | 2 | **286** | 73% |
| `Fireball`(精确英文名) | 1 | **220** | 56% |
| `真知术`(唯一精确名) | 1 | **326** | 83% |
| `火`(1 字,精确模式) | 48 | 48 | ✅ 正常 |

物品卡同款问题:

| 搜索词 | 期望 | 实测 |
|---|---|---|
| `闪烁甲`(唯一精确名) | 1 | **385**(92%) |
| `shuoshanjia`(拼音) | 1 | **408** |
| `护甲` | ~10 | **378** |
| `zzz`(无匹配) | 0 | **196**(不显示空状态!) |

**根因**(`js/app.js` 法术书 / 物品卡同款):
```js
const useFuzzy = q.length >= 2;   // 2 字起启用模糊
function fuzzyScore(q, t) {
  if (t.includes(q)) return 1000 + q.length;        // 子串命中最强
  const qs = new Set(q); let cov = 0;
  qs.forEach(c => { if (t.indexOf(c) >= 0) cov++; });
  const coverage = qs.size ? cov / qs.size : 0;
  // ...
  if (coverage < 0.5 && sim < 0.4) return 0;       // ← 门槛过低
  return coverage * 50 + sim * 30 + lcs * 20;
}
```
- 中文短串(2~3 字)`coverage` 极易 ≥0.5(如"火球术" vs "火墙术"共享"火、术"=2/3=0.67),`sim` 也高,导致大量非目标条目得正分。
- `spellScore` 取 `max(fuzzyScore(q,zh), fuzzyScore(q,en), fuzzyScore(q,sc))`,任一字段得正分即纳入,进一步放大误伤。
- 排序虽按分数降序,但**子串命中(1000+)与误伤结果混在同一列表**,没有分层,用户要在几百条里找目标。
- **无匹配查询(zzz)不返回空状态**,反而显示 123~196 条无关结果——这是最伤用户体验的部分。

**建议**:
1. `coverage < 0.5` 门槛对 2~3 字查询提高到 0.75~0.8;或按查询长度动态设阈。
2. 子串命中(≥1000)的结果单独置顶,误伤结果折叠或降权后置于其后。
3. 无匹配时显示"没有匹配的法术/物品"空状态,而非一堆低分误伤。
4. 拼音层加载后,拼音查询应优先匹配拼音缓存,而非全量 fuzzyScore。

### 1.2 🟠 合集父壳缺 message 转发器,天赋法术贯通(A2)在合集中失效

**实测证据**(链路分段验证):
- 人物卡 iframe 选提夫林 → `grantedSpells()` 返回 `["奇术"]` ✅
- 人物卡 `broadcastGranted()` → `parent.postMessage` → **父壳确实收到** `{"type":"dnd:granted","spells":["奇术"]}`(探针捕获)✅
- 但法术书 iframe **未收到**,selCount 仍 0 ❌
- 反向验证:父壳手动 `spellbook.contentWindow.postMessage({type:"dnd:granted",spells:["奇术"]})` → 法术书成功加入,selCount=1,toast"已从角色卡同步 1 个天赋法术" ✅
- 法术书自发自收 postMessage → 也成功(监听器工作正常)✅

**结论**:链路三段(人物卡发送、父壳接收、法术书处理)**各自都正常**,唯独**父壳没有把收到的 `dnd:granted` 转发到三个 iframe**。`build.js` 的合集模板(入口页 + iframe + toggle 按钮的 script 段)缺少 `window.addEventListener("message", e => { if (e.data.type === "dnd:granted") { frames 各 postMessage } })`。

**影响**:文档 §六 与第 2 轮清单都声称 A2"天赋法术贯通"已修,但**只在独立打开的单工具场景成立**;在真正的合集(三 iframe)部署版里,用户建好提夫林/精灵角色,天赋法术不会自动流入法术书——这是主站默认使用形态下的功能性缺失。

**建议**:在 `build.js` 合集模板 script 段补父壳转发器:
```js
window.addEventListener("message", function(e){
  var d = e.data;
  if (!d || d.type !== "dnd:granted") return;
  for (var k in frames) { try { frames[k].contentWindow.postMessage(d, "*"); } catch(_){} }
});
```
